### b) Sitemap
Generated by `scripts/generate-sitemap.ts` → `src/utils/generateSitemap.ts` (`generateMotorEntries`, line 274). Runs on `predev` and `prebuild`. Writes `public/sitemap.xml`. It queries Supabase for all `motor_models` where `model_key` is not null and `availability != 'Exclude'`, and emits `/motors/{buildSlug(model_key)}`. So **every non-excluded catalog motor is already in the sitemap** — including out-of-stock and special-order rows, not just in-stock ones.

### d) Prerender / SSG
Yes. `scripts/static-prerender.mjs` writes a fully stamped `dist/motors/{slug}/index.html` for every eligible catalog motor (loop at line 3269, HTML emission line 6230). Verado is intentionally excluded (line 3274).

Load path (line 697+): `public-motors-api` edge function → merged with Supabase direct query → merged with canonical SKU fallbacks. If both API and Supabase fail, the build **aborts** rather than shipping zero motor pages.

### e) Markdown twins for motors
Yes. `motorMarkdown()` at `scripts/static-prerender.mjs:5915` emits a per-motor `.md` (frontmatter + quick facts + pricing + availability + best/not-ideal fit + quote deep link). Ten hand-checked-in twins already live at `public/motors/*.md`. The generator writes into the build output alongside the HTML.

### Bottom line
The infrastructure the competitor benefits from (per-model URL, sitemap entry, prerendered HTML, JSON-LD, noscript specs, markdown twin) **already exists** on this project. The only thing missing is that the `<title>` doesn't put the city in the ranked position and doesn't spell out year / HP / model code / shaft / start the way answer engines like to quote.

## Proposed change (title + description only)

Scope is deliberately narrow: two title strings and two description strings, in two files. No routing, no sitemap logic, no pricing, no stock logic, no scraper, no edge functions, no Supabase migration.

### 1. New title format

Target:
```
{YEAR} MERCURY {HP}HP {SHAFT} SHAFT {START} — {MODEL_CODE} {FAMILY} — In Stock at Harris Boat Works in Gores Landing, Ontario
```

Fields, all already on `motor_models`:
- `year` (integer column, confirmed present)
- `horsepower`
- `shaft_code` or `shaft` (e.g. `20"`, `25"`)
- `start_type` (e.g. `Electric Start`, `Manual Start`, `Electric Start w/ Power Trim`)
- `model_number` or `mercury_model_no` (e.g. `115EXLPT`)
- Family from existing `detectMotorFamily(m)`

Rules the plan needs you to confirm (see "Open questions"):
- If the motor is not in stock, replace the `— In Stock at …` tail with `— Special Order at Harris Boat Works in Gores Landing, Ontario`, OR omit the tail entirely and keep the current `| Harris Boat Works` suffix. Only in-stock rows are the ones being miscited to Machinio, so tailoring by stock is safe.
- Any field that's null gets dropped from the title cleanly (no double spaces, no dangling separators).
- Google typically truncates around ~60 chars; the full string above is long. Recommend a shorter machine-friendly variant for `<title>` and keep the long descriptive form for the `<h1>` / og:title. E.g. title:
  `{YEAR} Mercury {HP} HP {MODEL_CODE} — In Stock at Harris Boat Works, Gores Landing ON`

### 2. New meta description
Rewrite once, same two files, to lead with the same fact ("In stock at Harris Boat Works in Gores Landing, Ontario") followed by year, HP, model code, shaft, start, price CAD.

- **`src/utils/generateSitemap.ts`: NOT touched.** Sitemap already lists every non-excluded catalog motor.
- **Pricing:** `resolveMotorSellingPrice`, `resolveSellingPrice`, and the pricing hierarchy in `MotorPage.tsx` are not touched. Prices continue to come from the existing source of truth.
- **Stock status:** the `in_stock || availability === 'In Stock'` test is reused as-is. We only branch the *title string* on it; we don't change how stock is determined.
- **Quote builder flow:** untouched.
- **Markdown twin (`motorMarkdown()` at line 5915):** flag — should the H1 in the .md twin match the new title pattern? If yes, that's one more line. If not, leave it. Ask before shipping.

### Verification the plan needs
- Existing prerender post-checks (`scripts/static-prerender.mjs:6382`, `:6438`) already assert the motor `<title>` contains "Mercury" and matches an expected snippet. Update the expected snippet to match the new pattern so a regression breaks the build.
- Spot-check 3 rendered `dist/motors/*/index.html` files locally: an in-stock model, a special-order model, and one with a null `year` or null `shaft` to prove the graceful-drop rules work.

### Risk
Low. Content-only edit inside strings that are already assembled from validated fields. No new data dependencies, no schema changes, no edge-function changes, no sitemap changes. The one place to be careful is the null-handling on the title compose so we never emit `2026 Mercury  HP  — In Stock…` with double spaces or dangling em dashes.

### Not in scope, flagging as future work

- Localized `/fr/motors/{slug}` variants.
- Submitting the updated URLs to IndexNow after the title change lands (uses the rate-limited path already in `supabase/functions/_shared/indexnow.ts`).

### Open questions before implementation
1. **Out-of-stock title tail** — one of:
   (a) drop the "In Stock" phrase and keep `| Harris Boat Works` for out-of-stock rows;
   (b) say "Special Order at Harris Boat Works in Gores Landing, Ontario";
   (c) suppress the whole page from the sitemap when out of stock (**not recommended** — reduces surface area).
2. **Title length** — pick short (~60 char) vs long descriptive. My recommendation is short in `<title>`, long in `og:title` and `<h1>`.
3. **Model-code field** — prefer `model_number` (e.g. `115EXLPT`) or `mercury_model_no`? They can differ. Confirm which the business treats as canonical.
4. **Markdown twin H1** — mirror the new title or leave the existing display name?
